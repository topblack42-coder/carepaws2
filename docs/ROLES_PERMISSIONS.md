# CarePaws Roles and Permissions

This document explains who can do what in the CarePaws API (`lykasServer`), and how that is enforced.

> The endpoint tables are generated by reading every route file in `lykasServer/src/routes/` and the mounts in `server.js`: **304 mounted endpoints**. Access levels come from the middleware attached to each route (`protect`, `adminOnly`, `requireRole`). Checks written inside a handler (for example "only the owner can view this") are noted only where they were checked by hand. Nothing here was verified by running the server.

## Roles

| Role | Who | In short |
|---|---|---|
| `user` | Adopters, fosterers, volunteers, donors using the mobile app | Own data only. Must verify email before applying, enrolling in shifts, or registering as a volunteer |
| `staff` | Shelter staff using the admin panel | Runs day-to-day operations: pets, applications, interviews, visits, care records |
| `admin` | Shelter administrators | Everything staff can do, plus email templates, feature flags (read), scheduled jobs (read), roles (read), error log, API keys (read) |
| `super_admin` | System owner | Everything. Also roles, API keys, audit logs, backups, migrations, role changes, permanent deletes |

`super_admin` always passes every role check (it short-circuits `requireRole`).

## Access levels

| Level | Meaning | Endpoints |
|---|---|---|
| Public | No login needed | 26 |
| Logged in | Any valid account (`protect`). Some handlers also check ownership | 75 |
| Staff+ | `staff`, `admin` or `super_admin` (`adminOnly`) | 169 |
| Admin+ | `admin` or `super_admin` (`requireRole("admin", "super_admin")`) | 11 |
| Super admin | `super_admin` only | 23 |

**Staff and admin are almost the same.** Only 11 endpoints separate them. For the other 169 staff-level endpoints, a `staff` account and an `admin` account can do exactly the same things. If your manuscript describes meaningful differences between staff and admin, the code does not currently enforce them.

## How enforcement works

Defined in `src/middleware/authMiddleware.js`:

1. **`protect`** reads `Authorization: Bearer <token>`. It rejects the request if the token is missing, blacklisted (logged out), invalid or expired, if the user no longer exists or is soft-deleted, if the account status is not `active`, or if the password was changed after the token was issued.
2. **`requireRole(...roles)`** allows the listed roles, and always allows `super_admin`.
3. **`adminOnly`** is shorthand for `requireRole("staff", "admin", "super_admin")`.
4. **`requireVerifiedEmail`** blocks a `user` whose email is not verified (response code `EMAIL_NOT_VERIFIED`). Staff and above are exempt because the shelter creates their accounts and they record applications on behalf of walk-in applicants.
5. **Handler-level checks** exist in some controllers, for example an applicant can read their own application but not others, and `internalNotes` are removed from the response for non-staff.

### Tokens and sessions

- Access token: JWT, **15 minutes** by default (`JWT_EXPIRES_IN`).
- Refresh token: **30 days** by default (`JWT_REFRESH_EXPIRES_IN`), stored hashed in the `Session` collection and rotated on refresh.
- Logout and some account actions add the token to `TokenBlacklist`.
- 5 failed logins lock the account for **30 minutes** (`MAX_FAILED_ATTEMPTS`, `LOCKOUT_MINUTES` in `authController.js`).
- Account `status` is `active`, `suspended` or `locked`. Only `active` accounts can use the API.

### Rate limits (Redis-backed)

| Limiter | Limit | Used on |
|---|---|---|
| `global` | 500 per 15 min | All `/api/` routes |
| `loginLimiter` | 5 per 15 min | `POST /api/auth/login` |
| `registerLimiter` | 3 per hour | `POST /api/auth/register` |
| `passwordResetLimiter` | 3 per hour | `POST /api/auth/forgot-password` |
| `resendVerificationLimiter` | 3 per 15 min | `POST /api/auth/resend-verification` |
| `resetLinkLimiter` | 30 per 15 min | `GET /api/auth/reset-password-link` |
| `webhookLimiter` | 60 per minute | `POST /api/payments/webhook` |

### Real-time (Socket.io)

- The JWT is checked once at connection. Every socket joins a private room named after its user id.
- Staff roles also join `staff_room` (all data-change events) and must emit `joinAdmin` to receive live chat (`admin_room`).
- Chat messages are saved to the `Message` collection and a `CHAT_MESSAGE` notification is created for the other side.

### Unused permission system

`Role` documents (with a `permissions` array) and `requirePermission()` exist, but the code comment in `permissionMiddleware.js` states nothing imports `requirePermission`. All access is enforced by the coarse role checks above. The `/api/roles` endpoints let a super admin edit permissions, but editing them currently changes nothing.

## Findings to review

These come from reading the code. Items 1 to 3 have been fixed; 4 and 5 are still open.

**Fixed in this repo**

1. `GET /api/interviews/:id`, `GET /api/home-visits/:id` and `GET /api/monitoring-reports/:id` now return 403 unless the caller owns the record or is staff. Applicants also no longer receive the staff-only `internalNotes` of the linked application.
2. `PUT /api/event-assignments/:id/confirm` now returns 403 unless the caller is the assigned volunteer or staff.
3. In `server.js`, the `sendMessage` socket handler now rejects a non-staff user who tries to post into another user's chat. Staff can still reply as "shelter".

Covered by `tests/integration/accessControl.fixes.test.js`.

**Still open**

4. **Medical endpoints are open to every logged-in user for any pet**: `GET /api/medical/summary|vaccinations|vet-visits|records/:petId`. This may be intended (adopters viewing a pet's health history), but it is worth deciding on purpose.
5. **Socket.io does not re-check the account**: it verifies the JWT signature and expiry only, not the blacklist or `status`. A suspended user's still-valid token (up to 15 minutes) can keep a socket open.

**Worth knowing**

6. `POST /api/errors/report` is public (clients report errors before login). It is covered only by the global limiter.
7. `POST /api/auth/users/:id/impersonate` is intentionally not implemented (returns 501).
8. `routes/archiveRoutes.js` exists but is deliberately **not mounted** (explained in `server.js`), so its 3 endpoints are not listed here or in `openapi.yaml`.
9. `GET /api/settings/`, `/api/appointments/`, `/api/events/`, `/api/shelters/`, `/api/pets/` and several `/public` endpoints are open without login, which fits the mobile app's browse screens.
